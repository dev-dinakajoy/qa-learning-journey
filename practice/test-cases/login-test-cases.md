# Login Test Cases

## Feature

User Login

## Test Cases

| ID    | Test Case                       | Expected Result                   |
| ----- | ------------------------------- | --------------------------------- |
| TC001 | Login with valid credentials    | User is logged in                 |
| TC002 | Login with invalid password     | Error message is displayed        |
| TC003 | Login with invalid email        | Error message is displayed        |
| TC004 | Login with empty email          | Validation message is displayed   |
| TC005 | Login with empty password       | Validation message is displayed   |
| TC006 | Login with both fields empty    | Validation messages are displayed |
| TC007 | Login with invalid email format | Validation message is displayed   |

## What I Practiced

* Positive testing
* Negative testing
* Validation testing
* Expected vs actual behavior
* Writing clear test cases

## What I Learned

A test case should be specific enough that another tester can understand what to do and what result to expect.
