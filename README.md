# QA Learning Journey

Welcome to my **QA Learning Journey**  - a hands-on repository documenting my transition from **Software Development to Software Quality Assurance**.

After spending **over 4 years working as a Software Developer**, I’m expanding my perspective from building software to **testing, validating, and improving its quality**.

This repository documents that transition through learning notes, testing exercises, test cases, bug reports, practical experiments, and QA projects.

My goal is to combine my existing **software development experience** with strong **quality assurance and testing practices** to become a well-rounded **QA Engineer / Quality Engineer**.

---

## About Me

I'm a **Software Developer with 4+ years of experience** who is transitioning into **Software Quality Assurance**.

Working as a developer has given me practical experience with how software is designed, developed, debugged, tested, and maintained. I understand the development process from the inside, and I'm now learning to approach software from a tester's perspective.

* How software can fail
* How to identify defects before they reach users
* How to design effective tests
* How to validate requirements and acceptance criteria
* How to communicate bugs clearly
* How testing fits into the software development lifecycle
* How automation can improve testing efficiency
* How QA can contribute to building better software

## Goal

My goal is to become a capable **Software QA Engineer / Quality Engineer** who can contribute throughout the software development lifecycle.

I will start with a strong foundation in **Manual Testing and Test Design**, then progress into:

**Manual QA → API Testing → SQL → Test Automation → CI/CD → Quality Engineering**

This repository serves two purposes:

* **Learning Journal** - documenting what I learn and the lessons I gain through practice.
* **QA Portfolio** - demonstrating practical testing skills, projects, and my progression toward QA Engineering.

---

## Learning Philosophy

I don't want this repository to become a collection of copied tutorials.

Instead, I want to:

1. **Learn the concept**
2. **Understand why it matters**
3. **Practice it**
4. **Make mistakes**
5. **Document what I learned**
6. **Apply it to a project**
7. **Review and improve**

My goal is not simply to complete a QA roadmap.

I want to become capable of **thinking like a tester, finding meaningful problems, communicating them clearly, and helping development teams deliver better software.**
