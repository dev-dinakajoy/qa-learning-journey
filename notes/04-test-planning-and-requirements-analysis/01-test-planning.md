# Test Planning

## What is Test Planning?

Test planning is the process of deciding **what will be tested, how it will be tested, when it will be tested, who will perform the testing, and what resources are required**.

It happens before test execution and provides direction for the testing activities.

Test planning helps the QA team understand the scope, objectives, approach, resources, schedule, risks, and expected deliverables of testing.

---

## Why is Test Planning Important?

Without proper planning, testing can become:

* Unstructured
* Incomplete
* Difficult to track
* Difficult to estimate
* More likely to miss important risks or requirements

Test planning helps the team:

* Define the testing scope
* Identify testing objectives
* Determine testing types
* Identify resources and responsibilities
* Estimate timelines
* Prepare test data and environments
* Identify risks
* Define entry and exit criteria
* Define testing deliverables

---

## What Does a QA Tester Plan?

A QA tester may need to consider:

### 1. What should be tested?

Define the features and functionality within scope.

Example:

* User registration
* Login
* Restaurant search
* Shopping cart
* Order placement

### 2. What should not be tested?

Define functionality that is outside the current testing scope.

Example:

* Payment gateway
* Delivery processing

### 3. How will it be tested?

Determine the testing approach and testing types.

Example:

* Functional testing
* Regression testing
* Exploratory testing
* Smoke testing
* Usability testing
* Compatibility testing

### 4. When will testing happen?

Define the testing schedule.

Example:

* Requirement review
* Test case design
* Test execution
* Retesting
* Regression testing
* Test summary

### 5. Who will perform the work?

Identify roles and responsibilities.

Example:

* QA Lead
* QA Tester
* Product Owner
* Developer

### 6. What resources are required?

Examples:

* Test environment
* Browsers
* Devices
* Test data
* Database
* Testing tools

---

## Test Planning vs Test Execution

Test planning happens **before and during preparation for testing**.

Test execution happens when testers actually execute the test cases.

### Test Planning

> "How are we going to test this application?"

### Test Execution

> "Let's execute the tests and record what actually happens."

---

## Test Planning Output

One of the main outputs of test planning is the **Test Plan**.

A Test Plan documents the testing approach and provides a reference for the QA team and stakeholders.

---

## Key Takeaway

Test planning provides direction for testing.

A good test plan helps the QA team understand:

> **What to test + how to test + when to test + who will test + what resources are needed + what risks exist.**
